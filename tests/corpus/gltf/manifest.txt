# glTF/GLB corpus manifest for the M2 cooker (glb -> .mesh). One line per model; expected
# values are what the cooker should produce from that source after applying the naming
# conventions in docs/design/mesh-cook.md (mount_ / _lodN / col_ / _ / .NNN) and rejecting the
# cases docs/mesh-format-spec.md says to reject (Draco, sparse
# accessors). Columns:
#
#   path        relative to tests/corpus/gltf/. `generated/external_uri.gltf` is the entry
#               point for that case; its external_uri.bin / external_uri_albedo.png ride
#               along and are not listed separately.
#   expect      ok | error -- whether the cooker should produce a .mesh at all.
#   code        expected diagnostic code (bare number, no "K" prefix) when expect=error,
#               else 0. Confirmed against kiln::cook::GltfDiagCode (include/kiln/cook/cook.h):
#                 1002  unsupported required extension (KHR_draco_mesh_compression, and
#                       EXT_meshopt_compression until its decoder lands) -- Unsupported
#                 1003  sparse accessor -- Unsupported
#               Warnings (skipped LINES primitive, skipped tangent generation, dropped
#               extras keys, etc.) do NOT gate expect/code -- they're called out in notes.
#   parts       expected MeshPart record count in the cooked output. As implemented by the
#               M2 cooker: every node that carries a mesh (and is not a `_lodN` node, a
#               mount_, or inside a col_/_ subtree) becomes a PART. Nodes WITHOUT a mesh
#               (empties, cameras, lights) never become PARTs; their transforms are folded
#               into the descendant parts' translation/rotation (and any scale is baked into
#               the vertices). A part's parent is its nearest ancestor that is a part, or
#               kInvalid. So hierarchy-only root empties (hierarchy_parts' "ship", the
#               Khronos boxes' coordinate-fixup root) add no PART record.
#   lods        max MeshLod count across all parts (>=1 whenever parts>0).
#   materials   expected MaterialSlot count after `.NNN` suffix stripping and collapsing
#               distinct materials that strip to the same name AND have identical
#               resolved properties into one entry (mesh-format-spec §5.7).
#               A primitive with no material gets the cooker's MaterialSlot "default" (every
#               submesh needs a MATL index), which IS counted here.
#   textures    expected count of distinct SOURCE IMAGES actually referenced by a
#               resolved texture binding (an image reused across two slots, e.g. a packed
#               ORM image bound to both metallicRoughness and occlusion, counts once, not
#               once per binding). Images present in the file but bound to no
#               texture/material are not counted (see pbr_textures.glb).
#   mounts      expected Mount record count (mount_-prefixed empties).
#   notes       free text; a leading "?" on any numeric column above means this corpus
#               could not determine that value by inspection alone (real-world Khronos
#               files only) -- the cooker agent should pin it once the importer exists,
#               per the task instructions.
#
