# Hand-made glTF/GLB edge cases

Generated by `generate.py` (Python 3 standard library only: `json`, `struct`, `math`,
`zlib`; no third-party glTF exporter). Deterministic: no timestamps, sorted JSON keys,
floats rounded to 6 decimal digits before serialization. Re-running the script reproduces
every file byte-for-byte (verified by re-running and diffing).

Regenerate with:

```sh
python tests/corpus/gltf/generated/generate.py
```

No `gltf-validator` was available on this machine (`where gltf-validator` found nothing),
so each file is instead checked by the script itself right after writing it: the GLB
header/chunk framing is re-parsed and asserted (magic, version, declared length matches
file size, each chunk 4-byte aligned and in-bounds, exactly one JSON chunk present), and
for `external_uri.*` the `.gltf` is re-parsed and its external `.bin` / `.png` references
are resolved and size/signature-checked. This is a structural check, not full glTF schema
validation; if `gltf-validator` becomes available, run it over every file in this
directory and `../khronos/` as a follow-up.

All geometry is procedural (boxes and quads built from half-extents; see `box_flat`,
`box_subdivided`, `box_welded`, `quad` in `generate.py`), centered at the origin, Y-up,
CCW winding viewed from outside. Every mesh has normals unless the case is specifically
testing their absence. Materials are named explicitly so the `.NNN`-stripping and
material-library-by-name conventions (HANDOFF §4.1, §5.7) have something to bite on.

## Files

| File | Exercises | Cooker is expected to |
|---|---|---|
| `cube_basic.glb` | Baseline: 1 node, 1 primitive, POSITION+NORMAL+TEXCOORD_0, U16 indices, 1 factor-only material "paint". | Cook cleanly: 1 part, 1 LOD, 1 material, 0 textures, 0 mounts. |
| `hierarchy_parts.glb` | Multi-level hierarchy: empty root "ship" -> "hull" -> {"wing_l" (translated+rotated) -> "antenna", "wing_r" (same mesh as wing_l, mirrored via node `scale=(-1,1,1)`)}. | Cook 4 parts (hull, wing_l, wing_r, antenna) in topological order (`parent < self`); flip winding/normals for wing_r's negative-determinant transform; **not** emit a PART for the identity-transform, unprefixed root empty "ship" (see `../manifest.txt` header for the elision rule this corpus assumes). |
| `mounts_extras.glb` | `mount_` prefix convention; a rotated mount; `extras` with a mix of valid scalars and two invalid entries. | Emit 3 Mount records under "hull". `mount_gun.extras` = `{"slot":"hardpoint","size":2,"enabled":true,"bad;key":"x","nested":{"a":1}}`; the cooker must drop `"bad;key"` (semicolon in the key) and `"nested"` (non-scalar value) **with a warning each**, keeping `extrasStr = "enabled=true;size=2;slot=hardpoint"` (alphabetical key order, matching the source JSON's `sort_keys=True` serialization). |
| `authored_lods.glb` | `_lodN` suffix convention; `col_` and leading-`_` skip conventions. | Collapse "hull" (LOD0, 54v/48tri subdivided-cube stand-in for a high-poly mesh), "hull_lod1" (LOD1, 24v/12tri plain cube), "hull_lod2" (LOD2, 4v/2tri flat quad impostor) into **one** part "hull" with `lodCount == 3`, `geometricError == 0` for all three (authored, not simplifier-generated). Skip "col_hull" and "_helper" entirely — no PART, no MNTS, not even as hierarchy placeholders. |
| `multi_material.glb` | `.NNN` material-name stripping and de-dup. | One mesh, **4** primitives (not 3 — see note below): "metal", "glass" (`alphaMode=BLEND`), "decal.001", "decal.002". Strip `.001`/`.002` from the decal materials; since their resolved PBR properties are identical, collapse them into **one** MATL entry named "decal" — net 3 materials (metal, glass, decal), 4 submeshes. |
| `two_uv_sets.glb` | Two UV sets feeding different texture slots. | 1 quad, TEXCOORD_0 feeds `baseColorTexture`, TEXCOORD_1 feeds `occlusionTexture` (`texCoord: 1`). Two embedded PNGs, `images[].name` = "albedo" / "ao". `TextureBinding.uvSet` must reflect each texture's own `texCoord`. |
| `no_uv_no_normals.glb` | POSITION-only source. | An 8-vertex welded cube, no NORMAL, no TEXCOORD, no material. The cooker must generate NORMALs and **skip tangent generation with a warning** (no UVs to build a tangent basis from), and assign its own default material since none was authored. |
| `u32_indices.glb` | `componentType 5125` (UNSIGNED_INT) index buffer. | A plain 24-vertex cube whose *source* indices are U32 despite the small vertex count (legal glTF), specifically to exercise the cooker's U32 import/decode path independent of vertex count. `many_vertices.glb` (a >65535-vertex mesh to force U32 *organically*) was **intentionally not generated** — a 260x260 position-only grid is already ~811 KB before indices, which would blow well past this corpus's "as small as possible" / tests-are-cheap-to-run intent for a single edge case already covered by this file. |
| `pbr_textures.glb` | Full PBR texture slot set + a 16-bit image. | One material, one cube, with distinct baseColor/normal/metallicRoughness/occlusion/emissive textures. `hull_orm` (an ORM-packed image: R=occlusion, G=roughness, B=metallic) is bound to **both** `metallicRoughnessTexture` and `occlusionTexture` — 2 texture bindings, 1 image. A 5th image, `hull_height` (16-bit grayscale, `color_type=0`, `bitdepth=16`), exists purely as an `images[]` entry referenced by no texture, to give the future 16-bit PNG decode path something to load standalone. |
| `external_uri.gltf` + `.bin` + `.png` | The URI-resolution path (`.gltf` with external buffer + external image), as opposed to every other file here which is a self-contained `.glb`. | Same geometry/material shape as `cube_basic.glb` plus a `baseColorTexture`, but `buffers[0].uri = "external_uri.bin"` and `images[0].uri = "external_uri_albedo.png"`, both resolved relative to the `.gltf`'s own directory. 1 part, 1 material, 1 texture. |
| `draco_required.glb` | Required-extension rejection. | `extensionsRequired: ["KHR_draco_mesh_compression"]` on a primitive whose real geometry lives in a `KHR_draco_mesh_compression` extension object; the bufferView it points at is a few dummy bytes, not a real Draco bitstream. | `sparse_accessor.glb` | Sparse accessor rejection. | An 8-vertex welded cube whose POSITION accessor has no `bufferView` (implicit all-zero base) plus a full `sparse` override for all 8 corners — legal glTF, but per HANDOFF §4.1 / mesh-format-spec the cooker must reject it, with **K1003**. |
| `non_triangle.glb` | Mixed primitive topology in one mesh. | One LINES primitive (`mode=1`, 2 verts, no material) and one TRIANGLES primitive (`mode=4`) in the same mesh. ## Deliberate deviations from the task prompt, and why

- **`multi_material.glb` uses 4 primitives, not 3.** The task text lists four material
  names ("metal", "glass", "decal.001", "decal.002") for "three primitives". Testing the
  `.NNN`-collision-collapse behavior requires that **both** `decal.001` and `decal.002`
  actually be bound to a primitive each (otherwise there is nothing to collide/collapse).
  Four primitives is the smallest file that actually exercises the documented expectation.
- **`many_vertices.glb` was not generated.** See the `u32_indices.glb` row above — a real
  >65535-vertex mesh small enough to stay near the "as small as possible" spirit of this
  corpus doesn't exist (a minimal 260x260 position-only grid is already ~811 KB), and the
  U32 decode path is already exercised by `u32_indices.glb` without the extra weight.
- **`authored_lods.glb`'s "hull" is a 2x-subdivided cube (54 verts / 48 tris), not a
  literal 24-vertex mesh.** The task's own text already describes the plain, non-LOD
  cube as an example with "24 verts" (`box_flat` in `generate.py`); reusing exactly 24
  verts for both "hull" (LOD0) and "hull_lod1" (LOD1) would make the two LODs
  geometrically indistinguishable, defeating the point of the LOD-chain test. `hull` is
  built with `box_subdivided(segs=2)` instead, so the triangle count actually decreases
  down the chain (48 -> 12 -> 2).

## PNG writer

`write_png_bytes()` emits a minimal valid PNG: signature + `IHDR` + one `IDAT` (zlib
level 9, filter type `None` per scanline) + `IEND`. It supports 8-bit RGBA (`color_type
6`), used for every texture case, and 16-bit grayscale (`color_type 0`, `bitdepth 16`,
big-endian samples per the PNG spec), used only for `pbr_textures.glb`'s `hull_height`.
All source images in this directory are procedural gradients or solid colors
(`solid_rgba`, `gradient_rgba`, `gradient_gray16`), 8x8 or 16x16 pixels.
