# Diagnostic codes

This is the catalogue of kiln's stable diagnostic codes, the `Kxxxx` numbers that tools and
logs print. It is generated by hand from the enums in `include/kiln/*.h`; the enum is the
source of truth for which codes exist, this file is the source of truth for what they mean.

## 1. What a diagnostic is

A `Diagnostic` (`include/kiln/result.h`) is a small, non-owning record:

| Field | Meaning |
|---|---|
| `code` | Stable numeric id, printed as `Kxxxx`. `0` means "no code" (an ad hoc message with no catalogue entry). |
| `severity` | `Info`, `Warning` or `Error`. |
| `status` | The `Status` (a `Code` plus a detail byte) that the diagnostic accompanies, if any. |
| `asset` | The asset path or id the diagnostic is about. May be empty. |
| `where` | A location within the asset: node, material, section, blob index, and so on. May be empty. |
| `message` | A human-readable, printf-formatted description. |

A diagnostic is not the same thing as a `Status`. `Status` is the 4-byte value every fallible
call returns, cheap enough to propagate through every layer with no allocation. A `Diagnostic`
is the human-readable explanation of *why*, produced only at the point in the code that knows
the details, and delivered to a caller-supplied `DiagSink`. One failure can carry both: the
`Status` for control flow, the `Diagnostic` (with its `Kxxxx` code) for logs and tools. See
`docs/design/error-model.md` for the full error model.

Codes are **stable once released and append only**. A code's number and meaning never change
and are never reused for something else; retiring a check does not free its number. This is
what lets a game team grep their logs for `K4013` across engine versions and get a consistent
answer.

### How tools print a diagnostic

`log_diag_sink()` (`src/core/result.cpp`) is the sink most tools pass around; it forwards each
diagnostic to the log under category `diag`. When `code` is non-zero it formats:

```
K4013 <asset> <where>: <message> (<status name>)
```

For example:

```
K4013 ship_hauler_a.mesh blob 3: table not sorted by encodedOffset or ranges overlap (corrupt)
```

`<asset>` and `<where>` are each omitted (along with their separators) when empty. `<status
name>` is `code_name(status.code)`, the snake_case name of the accompanying `Status` (`corrupt`,
`validation_failed`, `unsupported`, `version_mismatch`, `invalid_argument`, and so on — see
`code_name()` in `include/kiln/result.h`). When `code` is `0`, the leading `K0000`-style prefix
is dropped entirely and the sink prints just `<asset> <where>: <message> (<status name>)`.

## 2. Ranges

| Range | Area | Milestone | Status |
|---|---|---|---|
| K1000-1999 | glTF import (unsupported extensions, sparse accessors, Draco, bad node names, missing UVs) | M2 | not yet populated |
| K2000-2999 | Image import and encode (PNG decode, KTX2 pass-through, size and channel checks) | M2 | not yet populated |
| K3000-3999 | Settings resolution (invalid combinations, unknown keys) | M2 | not yet populated |
| K4000-4099 | `.mesh` validation and decode | M1 | populated, see §3.1 |
| K4100-4199 | KTX2 validation | M1 | populated, see §3.2 |
| K4200-4999 | Reserved for other cooked formats | — | unassigned |
| K5000-5999 | Runtime and store (store miss, corrupt entry, adapter failures, placeholder served) | M3 | not yet populated |
| K6000-9999 | Unassigned | — | unassigned |

Only K4000-4099 and K4100-4199 have codes defined today, in `include/kiln/mesh.h`
(`kiln::mesh::DiagCode`) and `include/kiln/ktx2.h` (`kiln::ktx2::DiagCode`) respectively. The
other ranges are reserved by `docs/design/error-model.md` for work that has not landed yet;
when it does, its codes are added to this file in the same change (see §4).

## 3. Codes

### 3.1 K4000-4099 — `.mesh` validation and decode

Source: `kiln::mesh::DiagCode` in `include/kiln/mesh.h`. Emitted by `MeshView::open()`,
`decode_blob()`, `decode_payload()` and `check_indices()` in `src/formats/mesh_read.cpp`, all at
`Severity::Error`. Where a code is emitted with more than one `Status`, both are listed; which
one applies depends on the specific check that failed (see "Meaning").

| Code | Name | Status | Meaning | Typical cause / fix |
|---|---|---|---|---|
| K4001 | `kDiagBadMagic` | Corrupt | File does not start with magic `KMSH`. | Not a `.mesh` file, or the file is truncated/corrupted at the front. Recook or re-fetch the asset. |
| K4002 | `kDiagVersion` | VersionMismatch | `versionMajor` differs from the loader, or `versionMinor` differs while major is 0. | File was cooked by an incompatible cooker version. Recook with a matching `kiln-cook`, or update the runtime. |
| K4003 | `kDiagHeaderSizes` | Corrupt, ValidationFailed | `fileSize` / `gpuDataOffset` / `gpuDataSize` / `payloadAlignment` / `payloadDecodedSize` are inconsistent (Corrupt), or the header has unknown flag bits set (ValidationFailed). | Corrupted file, or file written by a newer cooker using flags this runtime does not know. Recook or update the runtime. |
| K4004 | `kDiagSectionTable` | Corrupt | Section table offset/size is out of bounds, misaligned, or lists a duplicate section id. | Corrupted file or a cooker bug. Recook from source. |
| K4005 | `kDiagSectionMissing` | Corrupt | A required section (`MODL`, `STRS`, `LAYT`, `GPUD`, ...) is absent, has 0 records where at least 1 is required, or `MODL` has more than one record. | Corrupted file or an incomplete cook. Recook from source. |
| K4006 | `kDiagSectionBounds` | Corrupt | A section's byte range falls outside the file's CPU region, or `GPUD` is not the last section / does not match the header's `gpuDataOffset`/`gpuDataSize`. | Corrupted file. Recook from source. |
| K4007 | `kDiagRecordStride` | VersionMismatch, Corrupt | A section's `stride` is smaller than the current record type or not 4-byte aligned (VersionMismatch: file is likely from an incompatible version), or `count * stride` exceeds the section's byte size (Corrupt). | For VersionMismatch: recook with a compatible cooker. For Corrupt: recook from source; the file is malformed. |
| K4008 | `kDiagStringOffset` | Corrupt | A string offset (name, path, extras) points outside `STRS`, is not null-terminated, or `STRS` itself does not end with a null terminator. | Corrupted file or a cooker bug. Recook from source. |
| K4009 | `kDiagIndexRange` | Corrupt, ValidationFailed | A cross-reference index is out of range: part→lod, lod→submesh, lod→material, material→texture, mount→part (Corrupt); or a small enum-like field is out of its valid set, such as `alphaMode` or a texture `slot` (ValidationFailed). | Corrupted file, or (for the enum cases) a cooker/runtime version mismatch on an enum range. Recook from source. |
| K4010 | `kDiagLayoutRule` | ValidationFailed | A `VertexLayout` breaks a structural rule: stream/attrib counts out of range, non-4-aligned stride, attribute outside its stream's stride, unknown or non-vertex format, or stream 0 not exactly one `Position` attribute. | Cooker produced a layout that does not satisfy the mesh format spec (`docs/mesh-format-spec.md` §5). File bug in the cooker, or hand-edited file. |
| K4011 | `kDiagPartOrder` | ValidationFailed | A `MeshPart.parent` index is not strictly before its own index (parts must be topologically ordered). | Cooker bug in part ordering. Recook from source. |
| K4012 | `kDiagLodRange` | Corrupt, ValidationFailed | A LOD's stream or index range falls outside the decoded payload, is not fully covered by blobs, or has `kInvalid` where a used stream needs an offset (Corrupt); or a used stream's offset is misaligned, an unused stream has a non-`kInvalid` offset, or `indexType` is out of range (ValidationFailed). | Corrupted file, or a cooker bug in payload layout. Recook from source. |
| K4013 | `kDiagBlobTable` | Corrupt | `BLOB` table entry is outside `GPUD` or the decoded payload, the table is not sorted by `encodedOffset`, ranges overlap, `lodRank` decreases along the table, or a `codec == None` blob has `encodedSize != decodedSize`. | Corrupted file, or a cooker bug in blob table construction. Recook from source. |
| K4014 | `kDiagBlobEncoding` | ValidationFailed | A blob's codec/filter pair is not in the spec's allowed table, `kBlobOuterZstd` is set with a non-meshopt codec, unknown blob flag bits are set, `elementSize` is 0, `decodedSize` is not a multiple of the codec's unit, offsets are not 16-byte aligned, or a U8 index blob uses a meshopt codec. | Cooker bug producing an encoding the spec (`docs/mesh-format-spec.md` §5.9) forbids. Recook from source. |
| K4015 | `kDiagBlobUnsupported` | Unsupported | Blob's codec or filter id is unknown to this build, or is known but not compiled into this runtime (v0.5 runtime decodes only `Codec::None` / `Filter::None`). | File uses a compression codec newer or richer than this runtime supports. Update the runtime, or recook with a codec this runtime version supports. |
| K4016 | `kDiagPayloadRaw` | Corrupt | `kPayloadRaw` header flag is set but a blob (or `gpuDataSize` vs `payloadDecodedSize`) violates the required identity conditions (same codec `None`, filter `None`, no flags, `encodedOffset == decodedOffset`, `encodedSize == decodedSize`). | Cooker bug: set the raw-payload flag without actually writing an identity layout. Recook from source. |
| K4017 | `kDiagChecksum` | Corrupt | A decoded blob's xxh32 does not match the `checksum` stored in its `PayloadBlob` entry. | Bit-level corruption of the file (disk, transfer, or decoder bug). Recook or re-fetch, and re-run with `DecodeOptions::verifyChecksums` in a debug build to localize it. |
| K4018 | `kDiagIndexAlign` | ValidationFailed | A LOD's `indexOffset` is not a multiple of the index size (`index_size(indexType)`). | Cooker bug in payload layout. Recook from source. |
| K4019 | `kDiagMountOrder` | ValidationFailed | `Mount` records are not sorted by `nameHash` (required for the binary search in `find_mount`). | Cooker bug in mount table construction. Recook from source. |
| K4020 | `kDiagIndexValue` | ValidationFailed | (Tools-only check, `check_indices()`.) An index value is `>= vertexCount`, or an index plus `vertexBase` falls outside `[0, vertexCount)`. | Cooker bug producing out-of-range geometry indices, or corrupted index buffer. Recook from source. |
| K4021 | `kDiagDecodeSize` | InvalidArgument, Corrupt | Caller passed a destination or encoded span whose size does not match what the blob or header declares (InvalidArgument: caller/loader bug); or a `codec == None` blob's encoded and decoded sizes differ, or a decoder's actual output size does not match `decodedSize` (Corrupt: file is malformed). | InvalidArgument: fix the caller to pass correctly sized spans. Corrupt: recook from source. |
| K4022 | `kDiagTruncated` | Corrupt, InvalidArgument | The supplied buffer is shorter than the header, section table, or `gpuDataOffset` require (Corrupt); or the buffer pointer is not 8-byte aligned (InvalidArgument). | Corrupt: file is truncated, re-fetch or recook. InvalidArgument: fix the caller to hand `MeshView::open()` an 8-byte-aligned buffer. |
| K4023 | `kDiagBufferAlignment` | `InvalidArgument` | Error | The buffer passed to `MeshView::open` is not 8-byte aligned. | Allocate the CPU region with at least 8-byte alignment (any `Allocator` result or `Vec<u8>` qualifies). |

### 3.2 K4100-4199 — KTX2 validation

Source: `kiln::ktx2::DiagCode` in `include/kiln/ktx2.h`. Emitted by `Ktx2View::open()` in
`src/formats/ktx2_read.cpp`, at `Severity::Error` unless noted otherwise.

| Code | Name | Status | Meaning | Typical cause / fix |
|---|---|---|---|---|
| K4101 | `kDiagKtxIdentifier` | Corrupt | The 12-byte KTX2 file identifier does not match. | Not a KTX2 file, or the file is truncated/corrupted at the front. Re-fetch or recook. |
| K4102 | `kDiagKtxTruncated` | Corrupt | The supplied span is too short for the header, level index, DFD, or KVD that the header describes. | Caller passed only a partial read (see `Ktx2View::metadata_size()`), or the file itself is truncated. Read the full metadata prefix, or re-fetch/recook the file. |
| K4103 | `kDiagKtxFormat` | Unsupported | `vkFormat` is `Undefined`, or is a format this build has no `FormatInfo` for. | Texture was cooked to a format this runtime version does not know. Recook to a supported format, or update the runtime. |
| K4104 | `kDiagKtxTypeSize` | Corrupt | `typeSize` does not match what the format requires (1 for compressed formats, bytes-per-channel otherwise). | Corrupted or hand-edited header. Recook from source. |
| K4105 | `kDiagKtxDimensions` | Corrupt, Unsupported | `pixelWidth` is 0, `faceCount` is neither 1 nor 6, a cube map's faces are not square, `levelCount` exceeds the full mip chain, or a level's byte length overflows (Corrupt); or the texture is 1D (`pixelHeight == 0`) or 3D (`pixelDepth != 0`), neither supported in v0.5 (Unsupported). | Corrupt: recook from source. Unsupported: this runtime only reads 2D textures (optionally arrays and cubes) in v0.5; reshape the source asset or wait for 1D/3D support. |
| K4106 | `kDiagKtxLevelIndex` | Corrupt | A level index entry has `byteLength != uncompressedByteLength`, a byte length that disagrees with the computed dimensions, a misaligned `byteOffset`, an offset overlapping the metadata, or levels not stored smallest-first. | Corrupted file or a cooker/writer bug. Recook from source. |
| K4107 | `kDiagKtxSupercompression` | Unsupported, Corrupt | `supercompressionScheme` is not `None` (Unsupported: v0.5 has no supercompression support); or `sgdByteLength` is non-zero despite no supercompression scheme (Corrupt). | Unsupported: recook without supercompression, or wait for scheme support. Corrupt: recook from source. |
| K4108 | `kDiagKtxDfd` | Corrupt (Error), kOk (Warning) | Malformed data format descriptor: `dfdByteLength` too small, `dfdByteOffset` misaligned or overlapping the level index, truncated, `totalSize` field disagreeing with `dfdByteLength`, or a basic block size that does not fit (Corrupt/Error). Separately, a non-failing Warning is emitted when the DFD's `transferFunction` disagrees with the sRGB-ness implied by `vkFormat`; the reader trusts `vkFormat` and continues. | Error case: recook from source. Warning case: informational only; the cooker/writer that produced the DFD should be checked for sRGB-flag consistency, but the file loads fine. |
| K4109 | `kDiagKtxKvd` | Corrupt | `kvdByteOffset`/`kvdByteLength` misaligned, truncated, overlapping the DFD, or the key/value entries themselves are malformed. | Corrupted file or a writer bug. Recook from source. |

## 4. Adding a code

1. Pick the next free number in the owning range (see §2). Never reuse or renumber an existing
   code, even one that later becomes dead code; once released, a code's meaning is permanent.
2. Add it to the `DiagCode` enum in the module's public header (for example
   `include/kiln/mesh.h` or `include/kiln/ktx2.h`), with a one-line doc comment.
3. Add a row to the matching table in this file, in the same change. This file and the enum
   must never drift apart: a code with no row here, or a row with no enum entry, is a bug.
4. Write tests (and any other code) against the enum name (`kiln::mesh::kDiagBlobTable`), never
   against the bare number (`4013`). The number is for logs and artists; the name is for code.
